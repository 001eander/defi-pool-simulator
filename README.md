# defi-pool-simulator

去中心化金融（DeFi）流动性池仿真（区块链 · DeFi）—— 决策仿真课程实践案例

## 开发环境

依赖由 uv 管理，Python 版本固定在 `.python-version`。仿真引擎为 salabim，结果分析使用 pandas 与 matplotlib。

```bash
uv sync          # 安装依赖（含 dev 组）
uv run pytest    # 运行测试
```

源码位于 `src/defi_pool_simulator/`。

## 仿真模型

第2次课的概念模型已实现为 salabim 离散事件模型，时间单位为小时。同刻事件按「外部价格 > LP 操作 > 交易」排序；交易与 LP 操作服务时长为 0，不形成等待队列。

```bash
uv run python -m defi_pool_simulator --replications 10 --output-dir results
```

可选参数：`--seed`、`--fee-rate`、`--price-sigma`、`--duration-hours`。

| 输出文件 | 内容 |
|---|---|
| `results/replications.csv` | 每次重复仿真的标量指标 |
| `results/snapshots.csv` | 每小时储备、价格、手续费与无常损失快照 |
| `results/summary.csv` | 各指标的均值、标准差与 95% 置信区间半宽 |

指标口径：

- 滑点为成交均价相对池内即时价的偏离比例，包含手续费。
- 累计手续费按成交前池内价格折算为 Token B。
- 无常损失以初始外部价格为基准，按 `1 - 2√k / (1 + k)` 计算，`k` 为外部价格比；LP 净收益为累计手续费减无常损失。

| 模块 | 职责 |
|---|---|
| `parameters.py` | 案例参数、交易类型与参数校验 |
| `amm.py` | 恒定乘积定价、滑点、手续费、LP 份额与无常损失 |
| `metrics.py` | 交易结果累计、小时快照与单次仿真结果 |
| `model.py` | salabim 到达流、事件处理与同刻优先级 |
| `runner.py` | 多次重复、汇总统计与 CSV 输出 |
| `__main__.py` | 命令行入口 |

## 一、案例背景

某去中心化交易所（DEX）运营一个自动化做市商（AMM）流动性池，用户可以在池中进行代币兑换交易。仿真时段为 7 天（168 小时），以小时为时间单位。

### 流动性池状态

- 池中有两种代币：Token A 和 Token B
- 初始储备：100 万枚 Token A 和 200 万枚 Token B
- 初始价格：1 Token A = 2 Token B

### 用户交易

用户到达流动性池进行兑换交易，到达间隔服从指数分布，均值为 5 分钟。

### 交易类型与规模

| 交易类型 | 占比 | 交易规模（Token A） | 滑点容忍度 |
|---|---|---|---|
| 小额交易 | 60% | 100—1000 枚 | 1% |
| 中额交易 | 30% | 1000—10000 枚 | 3% |
| 大额交易 | 10% | 10000—50000 枚 | 5% |

### AMM 价格机制

- 采用恒定乘积做市商模型：**储备A × 储备B = 常数**
- 交易价格由池中两种代币的储备量比例决定
- 交易规模越大，滑点越高（价格影响越大）
- 每笔交易收取 0.3% 的手续费，手续费添加到流动性池中

### 流动性提供者（LP）

- 流动性提供者向池中添加/移除流动性
- LP 添加流动性的到达间隔为平均 2 小时（指数分布），每次添加 1 万—10 万枚 Token A（离散均匀分布）及对应数量的 Token B
- LP 移除流动性的到达间隔为平均 3 小时（指数分布），每次移除 1 万—5 万枚 Token A（离散均匀分布）及对应数量的 Token B

### 无常损失

- 当 Token A / Token B 的市场价格发生变化时，流动性提供者可能遭受无常损失
- 外部市场价格变化由随机游走模拟（每小时的 Token A 价格变化率为 ±2%，正态分布）

## 二、关键参数汇总

| 参数 | 数值 |
|---|---|
| 初始储备（Token A / Token B） | 100 万枚 / 200 万枚 |
| 初始价格 | 1 A = 2 B |
| 交易到达间隔 | EXPO(5) min |
| 交易手续费率 | 0.3% |
| LP 添加流动性间隔 | EXPO(2) h |
| LP 移除流动性间隔 | EXPO(3) h |
| 外部价格变化率 | NORM(0%, 2%) / h |
| 仿真运行时间 | 168 h（7 天） |
| 建议 Replications | 10 次 |

## 三、核心决策问题

- 7 天内，流动性池的总交易量（Token A）是多少？总手续费收入是多少？
- 池中两种代币的储备量和价格如何变化？
- 大额交易的平均滑点是多少？是否在用户容忍范围内？
- 流动性提供者的无常损失是多少？手续费收入能否覆盖无常损失？
- 如果外部市场价格大幅波动（价格变化率标准差从 2% 增加到 5%），对 LP 收益有何影响？
- 如果交易手续费率从 0.3% 提高到 0.5%，对交易量和 LP 收入有何影响？
- 如果大额交易占比从 10% 提高到 20%，滑点会增加多少？

### 期末大作业（最终项目报告）要求

以本小组实际完成的案例（DeFi 流动性池仿真）为对象撰写，按照"现实问题—决策问题—系统分析—概念模型—数据参数—软件模型—实验设计—结果分析—模型验证—方案优化—管理建议"介绍决策仿真全过程。报告结构（见模板）：

1. 案例摘要（300–500 字）+ 关键词
2. 一、案例背景（行业背景、运行情境、管理痛点、核心决策问题）
3. 二、系统描述与问题定义（研究对象、系统边界、实体/资源/活动、运行规则、决策变量与评价指标）
4. 三、概念模型（构建思路、流程与事件逻辑、关键状态变量、模型假设）
5. 四、数据与仿真参数（数据来源、到达/服务过程参数、资源与容量参数、决策规则与阈值参数、参数合理性检查）
6. 五、仿真模型构建（总体结构、实体生成、决策逻辑、服务过程与资源配置、输出统计、与概念模型对应关系）
7. 六、仿真模型验证（逻辑验证、参数一致性、极端条件检验、现实合理性检验）
8. 七、实验设计（实验目的、基准方案、实验因素与方案、运行设置、输出指标）
9. 八、仿真结果与分析（基准结果、方案比较、瓶颈分析、关键因素、方案权衡、主要发现）
10. 九、方案优化（优化问题、方案设计、优化前后比较、稳健性分析、最终方案）
11. 十、管理建议（主要管理问题、三条管理建议、实施条件与风险）
12. 十一、结论与项目反思（结论、创新点、模型局限、后续方向）
13. 十二、AI 辅助建模与研究过程说明
14. 参考资料 + 附录（模型截图、关键参数、运行结果、验证与优化记录、小组分工）

写作原则：以管理问题为主线，以仿真模型为核心，以实验结果为证据，以管理建议为落点；不要写成软件操作说明，不要简单堆积模型截图和运行输出。
