# defi-pool-simulator

去中心化金融（DeFi）流动性池仿真（区块链 · DeFi）—— 决策仿真课程实践案例

## 一、案例背景

某去中心化交易所（DEX）运营一个自动化做市商（AMM）流动性池，用户可以在池中进行代币兑换交易。仿真时段为 7 天（168 小时），以小时为时间单位。

### 流动性池状态

- 池中有两种代币：Token A 和 Token B
- 初始储备：100 万枚 Token A 和 200 万枚 Token B
- 初始价格：1 Token A = 2 Token B

### 用户交易

用户到达流动性池进行兑换交易，到达间隔服从指数分布，均值为 5 分钟。

### 交易类型与规模

| 交易类型 | 占比 | 交易规模（Token A） | 滑点容忍度 |
|---|---|---|---|
| 小额交易 | 60% | 100—1000 枚 | 1% |
| 中额交易 | 30% | 1000—10000 枚 | 3% |
| 大额交易 | 10% | 10000—50000 枚 | 5% |

### AMM 价格机制

- 采用恒定乘积做市商模型：**储备A × 储备B = 常数**
- 交易价格由池中两种代币的储备量比例决定
- 交易规模越大，滑点越高（价格影响越大）
- 每笔交易收取 0.3% 的手续费，手续费添加到流动性池中

### 流动性提供者（LP）

- 流动性提供者向池中添加/移除流动性
- LP 添加流动性的到达间隔为平均 2 小时（指数分布），每次添加 1 万—10 万枚 Token A（离散均匀分布）及对应数量的 Token B
- LP 移除流动性的到达间隔为平均 3 小时（指数分布），每次移除 1 万—5 万枚 Token A（离散均匀分布）及对应数量的 Token B

### 无常损失

- 当 Token A / Token B 的市场价格发生变化时，流动性提供者可能遭受无常损失
- 外部市场价格变化由随机游走模拟（每小时的 Token A 价格变化率为 ±2%，正态分布）

## 二、关键参数汇总

| 参数 | 数值 |
|---|---|
| 初始储备（Token A / Token B） | 100 万枚 / 200 万枚 |
| 初始价格 | 1 A = 2 B |
| 交易到达间隔 | EXPO(5) min |
| 交易手续费率 | 0.3% |
| LP 添加流动性间隔 | EXPO(2) h |
| LP 移除流动性间隔 | EXPO(3) h |
| 外部价格变化率 | NORM(0%, 2%) / h |
| 仿真运行时间 | 168 h（7 天） |
| 建议 Replications | 10 次 |

## 三、核心决策问题

- 7 天内，流动性池的总交易量（Token A）是多少？总手续费收入是多少？
- 池中两种代币的储备量和价格如何变化？
- 大额交易的平均滑点是多少？是否在用户容忍范围内？
- 流动性提供者的无常损失是多少？手续费收入能否覆盖无常损失？
- 如果外部市场价格大幅波动（价格变化率标准差从 2% 增加到 5%），对 LP 收益有何影响？
- 如果交易手续费率从 0.3% 提高到 0.5%，对交易量和 LP 收入有何影响？
- 如果大额交易占比从 10% 提高到 20%，滑点会增加多少？

## 四、重点 Arena 模块

| 模块 | 用途 |
|---|---|
| Create | 生成交易、LP 添加/移除流动性 |
| Assign | 分配交易类型、规模、价格变化 |
| Decide | 交易类型分流、买卖方向判断 |
| Process | 交易执行、流动性添加/移除 |
| Variable | 跟踪储备量、价格、累计手续费 |
| Record | 记录交易量、滑点、无常损失等 |
| ReadWrite | 输出储备和价格时间序列 |
| Dispose | 交易完成 |
